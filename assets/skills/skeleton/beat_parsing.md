# 节拍解析与分段（Beat Parsing & Segmentation）

把定稿剧本拆成「源剧情账本 E##」，再合并为分段 G##。你只导演，不编剧。

## 全量原子节拍解析

1. 按剧本原文顺序逐条登记节拍，编号 `E01/E02/...`，**全部保留，不筛掉、不合并、不重排**。
2. 节拍类型 ∈ 对白 / 动作 / 反应 / 信息 / 过渡留白。
3. 每条记录：
   - `id`：E##。
   - `sceneSeq`：来源场次序号（对应剧本 `scenes[].seq`，同一场可含多条节拍）。
   - `type`：节拍类型。
   - `who`：谁做 / 谁说，无人称留空字符串。
   - `content`：动作或对白原文，不改写。
   - `object`：作用对象（道具/人/地点），无则空字符串。
   - `estDurationMs`：最低自然时长（毫秒）。
   - `tags`：五类关键标签数组，只标注不删减不重排，无则 `[]`。
4. 任何「会改变剧情状态」的句子必须能映射回某个 `E##`，否则视为新增剧情，删除。

## 五类关键标签

- 转折点
- 情绪峰值
- 信息增量点
- 决策点
- 沉默点

## 时长预算

- 对白按自然语速估算；串行动作/反应相加；并行动作取重叠，不重复计。
- 节拍最低时长 = 自然对白时间 + 必要停顿 + 必须串行动作/反应时间。
- 开场建立「辨认 → 反应 → 行动」的最低时间（借鉴 screenAdaptation §1：观众需要看清正在发生的事并形成等待）；依赖迟疑、尴尬或失落的段落保留反应时间，不套固定秒数。

## 分段

1. 给定单段时长上限（毫秒）。
2. 从前往后合并相邻节拍为段 `G01/G02/...`，每段总时长不超过上限；不删、不改、不改顺序。
3. `globalTimeRange` 为全局时间区间，如 `00:00-00:12`；段首从 00:00 起连续累计。
4. `batch` 只表示输出批次边界，不改全片顺序/段号/连续性。
5. 先全片规划再分批；批次大小只影响一次输出多少段，段号与时间轴不变（借鉴 Toonflow PART A A3）。

## 输出片段

```json
{
  "globalDurationMs": 55000,
  "beats": [
    {"id": "E01", "sceneSeq": 1, "type": "动作", "who": "角色A", "content": "拿起道具X", "object": "道具X", "estDurationMs": 2000, "tags": ["信息增量点"]}
  ],
  "segments": [
    {"id": "G01", "batch": 1, "durationMs": 12000, "globalTimeRange": "00:00-00:12", "beatRefs": ["E01", "E02"], "assets": {"characters": [], "scenes": [], "props": []}}
  ]
}
```

`segments[].assets` 结构见资产出镜状态规则，不得留字段缺失。
