三条必须最先处理的结论：

1. **刚交付的 M17 分镜侧产物可回溯实际失效**：`shot_providers.dart` 构造 `ShotService` 时未注入
   `revisionDao` / `attemptDao`，两者皆为可选参数、内部 `if (dao == null) return`，于是分镜图历史面板
   永远空、`shot_direction` / `shot_image` / `shot_video` 三类台账永无记录。测试夹具省略了完全相同的
   两项，所以 231 例全绿。这是「修根因不修症状」这条原则自己没被自己遵守的地方。
2. **Release 包无法联网**：`android/app/src/main/AndroidManifest.xml` 全文无 `uses-permission`，
   INTERNET 只存在于 `src/debug/` 与 `src/profile/` manifest，Release 构建的 manifest merger 拿不到它。
   CI 产出的 release APK 大概率全是无法联网的空壳。
3. **数据完整性靠注释约定，不靠编译期**：`revisionDao` / `attemptDao` 是可选构造参数 + 内部静默返回 +
   五处 `catch (_) {}` 无日志。任何一道单独成立都不会暴露，三道同时成立必然漏。

### P0-4 Settler 固化对 LLM 输出做 `as String` 强转
- **位置**：`lib/features/novel/truth_file_store.dart:227-233`
  ```dart
  final next = up['status']?.toString() ?? '';
  if (next.isEmpty) { up['status'] = HookStates.open; }
  final from = idx >= 0 ? hooks[idx]['status']?.toString() : null;
  if (!HookStates.allows(from, up['status'] as String)) {   // :233 抛 TypeError
  ```
- **触发**：LLM 在 `hookOps.upsert` 返回 `{"id":"h3","status":1}` 或 `{"status":true}`，此时 `next`
  非空、默认分支被跳过、`:233` 抛 `TypeError`。
- **后果**：`applyDelta` 中断，本轮定稿的 facts / characters / resources / summary / authorIntent /
  currentFocus **全部不落库**，算力已消耗，章节停在旧状态。
- **修复**：全程不 `as`，非法状态记入 `rejectedTransitions`（这本来就是 AGENTS.md 约定的降级路径）。

### P0-5 Settler 固化无事务包裹，三处写绕开乐观锁
- **位置**：`truth_file_store.dart:130-143`，5 个 `_applyX` 顺序 await，各自 `readRow` 取 revision、
  各自 `write` 提交，中途无回滚。
- **勘误**：本条原先写成「五个 `write()` 一个都没传 `expectedRevision`」，**该判断有误**。
  `_applyFacts` / `_applyCharacters` / `_applyResources` / `_applyHooks` / `_applySummary` 五处
  均已传 `expectedRevision: row?.revision`，乐观锁在生产路径上有效。真实缺陷是下面三条：
  1. **无事务**：P0-4 抛错后前三个已提交，成为「用户已审阅过的权威事实」，summary / authorIntent /
     currentFocus 缺失。TruthFile 除 revision 外无「定稿完成」痕迹，下一章写作带着半套状态继续跑。
  2. **`authorIntent` / `currentFocus` 无锁**：这两个走 `write` 而非 `_applyX`，读—改—写之间不校验
     revision，用户手工编辑与 Settler 并发会静默覆盖。
  3. **`rejectedTransitions` 无锁**：`_applyHooks` 末尾重读行后直接 `write`，与上面同一类窗口。
- **修复**：`applyDelta` 包 `attachedDatabase.transaction`，中途抛错整段回滚；新增
  `_writeTextLocked` 补锁 authorIntent / currentFocus；`rejectedTransitions` 写入带 `expectedRevision`。

### P0-6 备份导入把整个压缩包解压进内存
- **位置**：`lib/core/storage/backup_service.dart:289-290`（`peekProjectNames`）、`:330-331`（`importProject`）
  ```dart
  final bytes = await File(zipPath).readAsBytes();
  final archive = ZipDecoder().decodeBytes(bytes);
  ```
- **触发**：导入含图片/视频的备份包。PNG/MP4 几乎不可压缩，压缩包大小 ≈ 解压后大小，两份全量字节同时驻留。
- **放大**：设置页 `findConflicts` 先调 `peekProjectNames` 再调 `importProject`，**同一文件解压两次**。
  `_guardImportSize` 只限压缩后大小，压不住解压后膨胀（zip bomb）。
- **修复**：不 `decodeBytes` 整个 archive，只读 central directory 定位条目，按 `fileSize` 逐个流式写出，
  写入前对单文件做上限判断。

### P0-7 `deleteAssetCascade` 漏删 `assetRevisions`，必抛外键冲突
- **位置**：`lib/data/daos/cascade_dao.dart:84-89`，事务内只删 `assetRefs` + `assets`，
  漏 `assetRevisions`（`tables.dart` 中 `AssetRevisions.assetId` 引用 `Assets#id`）与该资产的

- **触发**：对任何生成过图片的资产调用（`asset_service.dart:322` 每次成功生成都写一条快照）。
- **当前状态**：**无人调用**，被掩盖。批量路径 `_deleteAssetsOfScript`（`:184`）是对的，先删了
  `assetRevisions`。
- **修复**：补删 `assetRevisions` 与台账行；同时给 16 处 `references()` 补 `KeyAction.cascade`（见 P1-3）。
