# 03 · 核心流程与 Prompt 设计

> 本文档定义五大核心流程的详细步骤、各阶段 Agent 职责，以及借鉴自 Toonflow / InkOS 的关键 Prompt 规则。这些规则将以「Skill 文件」形式内置在 App 中，随 Pipeline 各阶段加载。

---

## 0. 全局约定

- **事实/提案/未知三分法**（借鉴 Toonflow `storyDevelopment.md` §1「先分清事实、提案与未知」）：AI 输出必须区分「用户已提供的事实」「AI 的创作提案」「保持未知」，不能把提案冒充事实。
- **只导演不编剧**（借鉴 Toonflow A0.1）：进入「剧本 → 镜头」后，禁止新增/删除/替换剧情事件、改归属、改顺序、改因果。
- **结构化输出**：所有阶段结果用 JSON Schema 约束，便于落库和后续消费；LLM 用 JSON mode 或强制格式解析。
- **可编辑可回溯**：每个阶段产物用户可改，改后记录版本，下游阶段以最新确认版本为准。

## 1. 阶段 A：AI 写小说（借鉴 InkOS）

### 1.1 流程

```text
创意/一句话 → A1 建立设定(世界观/角色/大纲) → A2 逐章写作
   → A3 审校(一致性/伏笔/OOC) → A4 状态固化(TruthFiles) → 下一章
```

### 1.2 子步骤

| 步骤 | Agent | 输入 | 输出 |
|---|---|---|---|
| A1 设定 | Planner + Architect | 创意/题材/参考 | 世界观、角色矩阵、故事命题、大纲 |
| A2 写作 | Writer | 大纲 + TruthFiles 相关片段 | 本章正文（Markdown） |
| A3 审校 | Reviewer | 正文 + TruthFiles | 问题清单（带依据）+ 修改建议 |
| A4 修订 | Writer(Reviser) | 正文 + 问题清单 | 修订后正文 |
| A5 固化 | Settler | 定稿正文 | 更新 7 类 TruthFile |

### 1.3 关键规则（借鉴 InkOS）

- **TruthFiles 7 类**（本项目对 InkOS `story/state/*.json` 权威状态机制的适配）：世界事实（SPO 三元组+章节有效期）、角色矩阵、资源与道具、伏笔钩子（open/progressing/deferred/resolved/superseded）、章节摘要、作者意图、当前焦点。
- **审校维度**（借鉴 InkOS `inkos-story-review` 自适应审校矩阵——7 项必查：用户意图与约束、连续性与因果、人物动机与声音、场景功能与后果、信息与证据一致、文笔清晰与视点稳定、承诺与交付的情绪；本项目裁剪为核心维）：角色 OOC、时间线、伏笔回收、道具/资源一致性、文风一致、设定冲突；每个问题需给出证据、影响与最小修改方向。
- **修订模式**：`spot-fix`（定点修）/ `polish`（润色）/ `rewrite`（重写本章）；InkOS 另有 `rework`/`anti-detect` 暂不引入，后续按需扩展。
- **上下文注入**（吸收 InkOS Composer 思想）：写作时只注入「大纲 + 当前相关 TruthFile 片段 + 前几章摘要」，不塞全文，控制 token 并保证一致性；记录本章实际注入内容以便追溯。

### 1.4 核心 Prompt 骨架（Writer 示例）

```text
你是长篇小说写手。根据以下材料写第 N 章正文：

【故事命题】{谁想要什么，受什么阻碍，失败失去什么}
【本章大纲】{本章目标、关键事件、结尾变化}
【角色矩阵（相关角色）】{姓名/目标/当前状态/关系}
【世界观规则】{影响本章的规则}
【未闭合伏笔】{需要在意的伏笔}
【前情摘要】{前几章发生了什么}

写作要求：
1. 严格遵循角色设定，不做 OOC。
2. 推进本章大纲的事件，结尾留下与下章的衔接。
3. 保持文风统一，避免 AI 腔/套话。
4. 输出 Markdown 正文，约 {目标字数} 字。
5. 不新增设定中不存在的人物/道具/规则；确需新增时在末尾单独列出【新增提案】。
```

## 2. 阶段 B：小说 → 动漫剧本（借鉴 Toonflow）

### 2.1 流程

```text
确定改编范围 → 提取事件/人物/对白/未解信息
   → 视听化改编(叙述→动作, 心理→可见行为) → 场次/对白/声音 → 忠实度检查
```

### 2.2 关键规则（借鉴 sourceAndScript + screenAdaptation）

- **先锁定范围**：本次改编哪一集/哪几章，不全本硬塞。
- **提取四类信息**：事件顺序、人物关系与动机、重要对白、时间地点与物件变化、未解问题。
- **视听化转换**：叙述/心理 → 可见动作、可听对白、原文旁白或画内文字。
- **场景任务 vs 人物目标**：每场写清「目标 → 阻碍 → 行动 → 反应 → 策略调整 → 结果」。
- **信息差与揭示时机**：区分观众先知道 / 角色先知道 / 同时得知三种关系。
- **潜台词对白**：对白有目的，避免直说感受、复述画面。
- **原文依据映射（忠实度）**：每处视听表达都能映射回原文依据（screenAdaptation §1「把原文依据映射到视听表达」）；改编补充需标注为「改编提案」待确认。

### 2.3 剧本交付格式（借鉴 sourceAndScript 紧凑格式）

```text
本次范围与目标：
已确定的视觉、语言和声音要求：
总时长估算及硬约束：

场01｜空间与时段｜出场人物
人物的位置、起始状态、行动、阻力与可见结果。
人物名：完整对白。
必要的 OS/VO、音乐、音效、字幕或画内文字。
本场结束状态及转场。
```

### 2.4 核心 Prompt 骨架（Adapter 示例）

```text
你是动漫编剧，把小说改编为可制作的动漫剧本。仅改编本次指定范围，不改剧情事实。

【原文】{约定范围的原文}
【改编范围】{第X章 / 第X-Y节}
【忠实度要求】{严格保留事件与对白 / 允许合理压缩}

要求：
1. 提取事件顺序、人物关系与动机、重要对白、时间地点、物件变化、未解问题。
2. 把叙述和心理转为可见动作、可听对白或原文旁白，不新增剧情事件。
3. 每场写清场景任务、人物行动与结束状态。
4. 对白保留原文，不擅自改写。
5. 涉及新增对白/删并事件/改视角时，单列【改编提案】说明依据。
6. 输出 JSON：{ scenes: [{ seq, location, time, characters, action, dialogue[], sound, endState, transition }] }
```

## 3. 阶段 C：提取剧本骨架（借鉴 Toonflow PART A A2–A4）

### 3.1 流程

```text
定稿剧本 → 全量原子节拍解析(建立源剧情账本 E##)
   → 五类关键标签 → 单节拍时长预算 → 节拍合段(G01..) → 分批(Batch)
   → 资产出镜状态(按时间轴) → 分段提示词骨架
```

### 3.2 关键规则

**A2 全量节拍解析：**
- 原子节拍类型：对白 / 动作 / 反应 / 信息 / 过渡留白，**全部登记，不筛掉**。
- 每个节拍编号 `E01/E02/...`，记录：谁做/谁说、动作或对白、作用对象、原始顺序、是否含时间/位置/数量等事实。
- 任何「会改变剧情状态」的句子必须能映射回某个 `E##`，否则视为 AI 新增剧情，删除。

**五类关键标签（只标注，不删减、不重排）：** 转折点、情绪峰值、信息增量点、决策点、沉默点。

**A3 分段与时长预算：**
- 单段时长上限由模型决定（如 Seedance 2.0 ≤15s、2.5 ≤30s；图片分镜则按画面数）。
- `节拍最低时长 = 自然对白时间 + 必要停顿 + 必须串行动作/反应时间`；并行动作可重叠。
- 先全片规划再分批；批次只影响一次输出多少段，不改全片顺序/段号/连续性。

**A4 资产出镜状态：**
- 角色按时间轴登记出镜状态（实际出镜并说话 / 仅手部 / 画外仅对白等 9 类词表）。
- 场景登记锚点、机位、前中后景、空间关系。
- 道具登记段首位置/持有者、时间轴动作、段末状态、禁止项。

### 3.3 骨架 JSON Schema

```json
{
  "scriptId": "...",
  "globalDurationMs": 55000,
  "beats": [
    { "id": "E01", "type": "动作", "who": "角色A", "content": "拿起道具X",
      "object": "道具X", "estDurationMs": 2000, "tags": [] }
  ],
  "segments": [
    { "id": "G01", "batch": 1, "durationMs": 12000,
      "globalTimeRange": "00:00-00:12",
      "beatRefs": ["E01", "E02", "E03"],
      "assets": {
        "characters": [{ "name": "角色A", "timeline": [{"range":"00:00-00:05","state":"实际出镜并说话"}] }],
        "scenes": [...], "props": [...]
      }
    }
  ]
}
```

### 3.4 核心 Prompt 骨架（Director 骨架提取示例）

```text
你是分镜导演，从定稿剧本提取结构化骨架。遵守「只导演不编剧」。

【剧本】{定稿剧本}
【目标模型单段上限】{15s / 30s / 单张画面}

执行：
1. 按原文顺序拆出全部原子节拍(对白/动作/反应/信息/过渡)，逐条编号 E01..，全部保留。
2. 给节拍打关键标签(转折/峰值/信息增量/决策/沉默)，可重叠，无标签也保留。
3. 估算每个节拍最低自然时长(对白按自然语速，串行动作相加，并行动作重叠)。
4. 从前往后合并相邻节拍为段 G01..，每段不超过单段上限，不删不改不改顺序。
5. 按时间轴登记每段角色出镜状态、场景、道具状态。
6. 输出 JSON，遵守给定 Schema。任何改变剧情状态的描述必须映射回 E##，否则删除。
```

## 4. 阶段 D：生成动漫资产图片（借鉴 Toonflow assets.md）

### 4.1 资产规范

| 类型 | 默认版式 | 内容要求 |
|---|---|---|
| 角色 | 横向四视图参考板 | 头部特写 + 正面全身 + 右侧 90° 全身 + 背面全身，同一身份状态一致 |
| 场景 | 单张主视图 | 前中后景、出入口、通道、稳定地标，**不含人物/人影** |
| 道具 | 2×2 参考板 | 正面 + 右侧 90° + 背面 + 局部细节，同一物件结构一致 |

### 4.2 流程

```text
骨架资产清单 → 去重/合并别名 → 判定复用已有 vs 新建
   → 生成设计提案(外观锚点) → 生成图片 → 验收 → 登记已采用
```

### 4.3 关键规则

- 只生成**本集真实出现且需复用**的资产；对白提及但不出镜的角色不生成肖像。
- 换装/变身/伤势等影响跨段识别的变化建**变体**；瞬时表情/转身不单独建资产。
- 外观缺失时生成「设计提案」，标注为提案，不冒充原文事实。
- 角色四视图**不裁头、不截身、不切脚**，全身尺度一致。

### 4.4 核心 Prompt 骨架（角色四视图示例）

```text
{已确认风格}角色参考板，同一角色为{名称、身份或物种、年龄}。
外观锚点：{轮廓、体型、头部特征、发色、配色、服装、识别物}。
同一画面横向排列：头部特写、正面完整全身、右侧90°完整全身、背面完整全身。
各视角身份与状态一致，全身尺度一致，完整保留{身体结构}，不裁切、不重叠。
自然静态姿态，中性表情，{符合风格的简洁背景与光照}。
无剧情场景、额外角色、动作过程、无关说明字、水印或尺寸标注。
```

## 5. 阶段 E：生成动漫镜头（借鉴 Toonflow PART A A4–A9）

### 5.1 产物形态（需用户确认，见 01 文档）

- **方案 (a) 分镜图**：每个 Shot 生成一张静态分镜画面（快、低成本）。
- **方案 (b) 视频片段**：每个 Segment 生成视频片段（慢、高成本，借鉴 Seedance）。
- **方案 (c) 推荐**：先出分镜图供确认，再对确认的镜头生成视频。

### 5.2 分镜图流程（方案 a/c 的第一阶段）

```text
骨架(Segments + 资产) → 每镜头写分镜提示词(主体/景别/角度/构图/表演)
   → 绑定参考图(角色/场景/道具句柄) → 生成分镜图 → 验收
```

### 5.3 视频流程（方案 b/c 的第二阶段，借鉴 PART A）

```text
定稿分镜 → A5 站位双层坐标 → A6 表演层 → A7 运镜/段间衔接
   → A8 跨段连续性 → A9 分段提示词模板(按模型路由) → 生成视频
```

### 5.4 关键规则（借鉴 PART A 核心）

- **A5 站位**：每段自包含「世界坐标(轴线地标) + 画面坐标(当前机位) + 光源 + 道具位置 + 段末状态」5 块信息，不写「延续上一段」。
- **A6 表演**：情绪 = 行为副产品；微表情必须有源剧情依据 + trigger；只写本镜头可见的表演通道（脸/手/背影/脚/全身）。
- **A7 段间衔接**：相邻独立生成段至少满足「拍摄主体不同 / 景别差 ≥2 档 / 角度差 ≥90°」之一，避免错误续帧。
- **A8 连续性**：人物位置、道具持有、场景物理环境跨段校验；只继承源剧情已定义的状态。
- **A9 提示词模板**：按模型版本用不同外壳（2.0 资产标识式 / 2.5 Objective 式），但都包含 Reference binding、Immutable locks、Target duration、Timeline、Visual/Audio direction、Preserve、Avoid。

### 5.5 视频分段提示词模板（借鉴 A9.2，时间块 + 连续自然语言）

```text
Objective: {本段要完成的事件，不改剧情}
Reference binding:
- {{ref1}}：{角色}角色参考
- {{ref2}}：{场景}场景参考
Immutable locks: {人物绝对位置/道具持有/持续状态/不该出现的人物}
Target duration: {Xs}
Timeline:
【0:00-0:XX】
画面为{景别}，{角度}，主体是{角色}；{站位描述}；{运镜，固定时省略}；
{表演：可见行为}；同期对白「{对白原文}」。
（0:XX 结束，HARD CUT）
【0:XX-0:XX】
画面为{景别}，{角度}，主体是{角色}；{站位描述}；{表演}。
Visual direction: {画风/光源/色调}
Audio direction: {环境音/同期对白/BGM 依用户要求}
Preserve: {必须保持的剧情事实；人物位置与道具持有保持本段开头登记}
Avoid: {禁止新增/删除/替换/改顺序；不出现画面外的角色；无后期字幕；不叠化闪白甩镜}
```

### 6.4 M8 扩展 · 供应商能力联动 + 体验补全 + 成片合成 + 检查更新

> 借鉴 Toonflow 桌面版（`videoGenerationNode`/`generationSettings` 联动 + `MediaModel` 扩展 + FFmpeg 成片合成 + 桌面 updateServer→安卓 GitHub Releases）。以下为本轮新增功能的 Prompt/Skill 设计说明。

#### 6.4.1 视频参数能力联动（`ModelPresets` + 归一化）

Toonflow `videoGenerationNode` 的 `generationSettings` 根据 `MediaModel` 能力动态收敛 UI 选项。本项目等价实现：

- `ModelPresets.apply(modelId)`：在拉取新模型后自动补全 `videoModes`/`maxImageRefs`/`durationResolutions`（不覆盖用户已填字段）；支持 seedance 2.5/2.0、wan-3、minimax-hailuo、kling-1.6、seedream 4/4.5 系列。
- `normalizeDuration(int sec)`：模型能力变更时回落到合法值（最接近目标时长的合法档位）；能力未知时返回原值。
- `normalizeResolution(int sec, String resolution)`：按时长命中组合的合法分辨率并集，无匹配时取首个；能力未知时返回原值。
- UI 联动效果（`shot_detail_page.dart` `_ParamCard`）：切换模型后自动归一化时长/分辨率；分辨率 chips 改为 `selectedModel.resolutionsFor(duration)` 动态生成；音频三态（`audioDisabled`/`audioRequired`/`audioOptional`）决定音频开关是否禁用；首帧开关仅 `supportsStartFrame` 时显示。

#### 6.4.2 首帧通道（`first_frame` role）

Toonflow `videoGenerationNode` 中首帧/尾帧参考走独立 `first_frame`/`last_frame` role，与普通参考图（`reference_image`）分开计费与处理。本项目实现：

- `VideoGenParams.useFirstFrame`（bool，默认 false）：`true` 时分镜图作 `firstFramePath` 传入 `submit`；提交体中 `first_frame` 优先入 `metadata.references[0]`，余图按 `maxImageRefs` 取上限（缺省 9）。
- `shot_service.submitVideo`：先查 `ProviderModel.maxImageRefs`（按 params.modelId），将 `firstFramePath` 占 1 个参考位，`referenceImages` 取余量（`maxImageRefs - 1`）。

#### 6.4.3 媒体历史（版本切换 + 替换）

- `VideoTasks.outputPath`：每次成功轮询回填 `outputPath`（同镜头可有多条成功任务记录）。
- `shot_detail_page._HistoryVersions`：该镜头的成功任务列表（按 `createdAt` 倒序），当前版本（`shot.outputPath`）高亮显示；点击可调用 `selectVideoVersion` 切换（改 `shot.outputPath`）。
- `replaceVideo`：通过 `FilePicker.pickFiles(type: video)` 本地选取 ≤100MB 视频，经 `videoFileStore.save` 落应用私有目录，更新 `shot.outputPath/video/videoDone`。

#### 6.4.4 停止生成（本地取消）

- `cancelVideoTask(int videoTaskId)`：将该任务状态置为「已取消」，回滚对应 shot 到「分镜图已确认」状态；任务中心轮询自动跳过非「生成中/排队」任务，无需特殊处理。

#### 6.4.5 供应商 readme

- `ProviderConfigs.readme`（自由文本）：供应商说明，在设置页供应商卡片副标题区直接展示；支持一键备份导出（`backup_service.dart` 将 readme 包含在 zip 内）。

#### 6.4.6 FFmpeg 成片合成（`ShotComposeService`）

- 取脚本下所有 `videoDone=true` 且 `outputPath` 非空的 shot，按 `seq` 顺序本地 FFmpeg `-c copy` 快拼；任一缺失则整体失败并定位到首个缺失镜头。
- 快拼失败时自动回落逐段重编码 720p/24fps + concat filter；`manifest.json` 落档（输入列表 + 命令 + 时间戳）。
- `ffmpeg_kit_flutter_new` 社区 fork（上游 `ffmpeg_kit_flutter` 已归档）；`ReturnCode.isSuccess` 判成功，`getOutput()` 取错误日志。
- UI 入口：`script_detail_page` 底部「合成成片」按钮（`_ComposeRow`），合成完成后可 `SharePlus` 分享 mp4。

#### 6.4.7 检查更新（GitHub Releases）

- `UpdateChecker.checkLatest()`：GET `api.github.com/repos/xfygl11/newmove/releases/latest`，与本地 `PackageInfo.version` 做 semver 比较（仅 major.minor.patch 前三段），离线静默返回占位不报错。
- 有更新时设置页 `_UpdateCheckTile` 高亮，点击 `url_launcher` 跳转 release 下载页。

### 6.5 M16 · 时长预算与分段准绳（第三轮 Toonflow 复研）

第三轮通读 Toonflow `workflow/SKILL.md` v2.7.0 全文 1406 行（PART A A0–A12）+ 8 个 references + 2 个 canvas 文件，把与本机固定管线相关的时长、分段、密度规则落成 skill 条款。§6.3 已记录的「A11.4 稳定性预检」「A12 细则」本轮不再重复；本节只补此前未成文的 **A2.3 时长公式、A2.4 合段与开段准绳、A3.0 段数下限、A3.2 对白硬门槛、A3.4 批次命名、A3.5 镜头密度、A6.9 微表情密度、A11.2 有限修正**。

#### 6.5.1 时长预算公式（`skeleton/beat_parsing.md`）

```text
节拍最低时长 = 自然对白时间 + 必要停顿 + 必须串行动作/反应时间
```

- 能自然同时发生的「说话 + 小动作」重叠计时；必须先后发生的因果动作相加。
- 长对白不按「长句固定 3–3.5s」粗估，按实际文本长度、停顿、语气估算。
- 不确定时宁可留 **10%–20% 呼吸余量**，不靠异常快语速硬塞。
- 关键停顿、反应、转身、走位不被对白完全吞掉。

理论最少段数 `⌈目标时长 / 单段上限⌉` 只回答「至少需要几段」，不强制实际段数等于它：对白/动作很轻可以 15+15+15+10，剧情密度高可以 12+11+11+11+10，只要每段不超上限、总和符合目标、剧情完整即可。原则是在「不过密」和「不碎片化」之间取平衡。

#### 6.5.2 合段六条准绳（A2.4，全部满足才继续合并）

1. 合并后总时长 ≤ 单段上限（含 10% 呼吸余量）；
2. 所有对白都能以自然语速说完；
3. 关键因果动作有完整过程；
4. 至少留得下必要反应与呼吸；
5. 不因塞得过满导致每 1–2 秒就强制切镜；
6. 段末可以形成清晰、可在下一段重新声明的状态。

#### 6.5.3 强制开新段六条（A2.4，命中任一即截断）

- 对白已经接近本段时间预算上限；
- 同段需要过多彼此竞争的动作/反应；
- 情绪或目标发生明确阶段切换；
- 场景或时间发生切换；
- 继续合并会破坏段间可独立生成性；
- 需要异常语速、瞬移动作或省略反应才能塞下。

#### 6.5.4 对白时长硬门槛（A3.2）

- 禁止用异常快语速解决时长不够；
- 禁止因为时长不够删词、改词、吞句尾；
- 冲突时优先压缩 AI 自己添加的空镜、无信息停顿、冗余运镜；用户原文明确要求的空镜、停顿、留白不得压缩或删除；
- 仍不够时在 UI 标注「时长约束冲突」，不删台词也不假装满足。

#### 6.5.5 批次（A3.4）

批次只表示一次输出多少段，不改变全片顺序、段号与连续性。**超过单批容量上限时保持全局段号连续，仅拆成多个 batch；不把未交付内容称为「被切掉」，统一称「下一批待交付段」。** 2–3 分钟剧情完全允许 2、3、4 个甚至更多批次。

#### 6.5.6 单段镜头密度（A3.5，推荐值不是硬上限）

- `2.0`：通常 1–2 个主要镜头，内容极轻时可 3 个，避免碎剪；
- `2.5`：通常 2–4 个主要镜头。
- 一段为了装下剧情需要持续高频 HARD CUT，优先拆段，优先于继续塞镜头。

本项目 M5 分镜图阶段每段拆 1–3 帧，与该密度一致；超出时提示拆分而不是限制生成。

#### 6.5.7 微表情密度（A6.9）

上限参考，非最低配额，允许 0 个：

| 段时长 | 每角色微表情事件 |
|---|---|
| ≤ 15s | 通常不超过 1–2 个 |
| 16–30s | 通常不超过 2–3 个 |

不得为了达到数量新增微表情；每个微表情必须有源剧情依据 + 触发点。

#### 6.5.8 有限修正机制（A11.2）

- 所有失败项一次性汇总，**只做一轮集中结构修正**；
- 结构修正只允许调整分段边界、镜头承载、时间预算、摄影表达与锁定信息；
- **不得修改任何 `E##` 的事件内容、执行者、对象、数量、顺序或台词**；
- 修正后只重新核对受影响项与它们的直接连续性，禁止 A11 ↔ A12 来回递归；
- 一轮修正后仍存在用户要求彼此不可同时满足的硬冲突（如严格 30s 但原文对白自然朗读已超 30s），保留用户原文并在总览标注冲突，不继续无限重算。

#### 6.5.9 集参数引导（对应 A0 输入判定）

A0 的「叙事规模 / 总时长要求 / 目标模型」三项在对话式工作流里靠提问确认；本项目落到剧本详情页的集参数卡（见 docs/05 §12）：`episodeNo`、`targetDurationMs`、`modelVersion`。`targetDurationMs` 为 0 表示由内容自然节奏决定，此时不做 `total_mismatch` 校验；`modelVersion` 未选时按通用默认 15000ms 分段。
