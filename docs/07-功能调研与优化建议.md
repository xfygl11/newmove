> 调研范围：`/tmp/opencode/` 下 7 个参考仓（AIComicBuilder / Toonflow-app / shuohao-skills /

## 1. 真正缺失的功能

### 1.1 角色侧

- **音色提示词**：shuohao-skills `novel-characters` 为每个角色产出「音色/音高/语速/口音/
  情绪」双语 voice-design prompt，可直接喂 TTS → 本项目 `CharacterSpec` 只有
  name/role/goal/state/relations 五字段，`Assets` 表也无对应列。
  **动作**：`CharacterSpec` + `Assets` 增补 `voiceDesign`，新增 `assets/skills/novel/voice_design.md`
  与角色四视图解耦（音色是 TTS 输入，不是图像输入）。
- **角色关系历史（append-only）**：goink `internal/character/types.go` 的 `CharacterRelation`
  是 `(source_id, target_id)` 配对 + `is_current` + 追加不可变，同一对角色的全部演变按
  `created_at` 排序即完整历史，还带 `chapter_id` 标注哪一章确立 → 本项目
  `CharacterSpec.relations` 是单一字符串，Settler 每次固化直接覆盖，关系反转无法回看。
  **动作**：新增 `CharacterRelations` 表（`bookId/source/target/description/chapterId/isCurrent/createdAt`），
  `_applyCharacters` 走 append-only + 事务。
- **角色关系图可视化**：goink `get_character_network` 返回 nodes + edges，有专门 UI →
  本项目 `character_manager_page.dart` 是线性列表。**动作**：二维布局画节点-有向边图。
- **角色分档上限**：shuohao `novel-outline` G1a-G1c（`lead-cap`/`support-cap`/`functional-cap`）
  强制主角组 1-N 人、副角/工具人各有上限 → 本项目角色无 `tier` 分档。
  **动作**：`CharacterSpec` 增补 `tier`，新增 `OutlineGate.characterTierCap`（3/6/10 起步）。
- **人物弧光与引用原文**：shuohao 每条角色画像附「原文逐字引文」+ `importance` + `arc` →
  本项目 `CharacterSpec.state` 是自由文本。**动作**：增补 `arc`（起点→弧光→终点）与
  `evidenceQuotes`，复用 `ReviewIssue.verifyQuotes` 的逐字核对范式。

### 1.2 世界观侧

- **地点系统（层级 + 空间连通）**：goink `Location`（`parent_location_id` 树）+
  `LocationRelation`（无向空间边），4 个工具覆盖 list/detail/network/create/update →
  本项目 `NovelBooks.world` 是一整段字符串，场景信息全塞在 `world_facts` TruthFile 里。
  **动作**：新增 `Locations` / `LocationRelations` 表，`Scenes.location` 从字符串改引用 `locationId`。
- **故事弧线（跨章并行叙事）**：goink `StoryArc`（3-5 条并行，四态 active/paused/completed/
  abandoned，带 `reactivate_at`）+ `ArcNode`（`target_reading_number` 与 `actual_chapter_id`
  追踪预估与实际）→ 本项目只有大纲 + 伏笔池。
  **动作**：新增 `StoryArcs` / `ArcNodes`，Settler 每章定稿后推进 `ArcNode.status`。
- **章节计划三档**：goink `ChapterPlan` 用 `scope ∈ {next, near, far}` 三槽位，
  `(novel_id, scope)` 唯一，第 N 章写作时全量注入 → 本项目只有 `outline` 一整段 Markdown。
  **动作**：TruthFile 新增 `chapter_plan` kind，Planner 写章前读三槽位、写完自动推进。
- **读者认知追踪**：goink 追踪「读者已知什么、在等什么答案、误认了什么」以精确控制悬念与
  反转时机 → 本项目无对应概念。**动作**：TruthFile 新增 `reader_knowledge` kind。
- **主场景上限 / 一次性场景规避 / 叙事道具上限**：shuohao `novel-outline` G2/G2b/G3
  （`scene-cap`/`once-scene`/`prop-cap`）→ 本项目完全没做。
  **动作**：新增 `OutlineGate`，`Assets` 增补 `isNarrative` 布尔区分叙事道具与场景陈设。
- **爽点表与钩子兑现闭环**：shuohao G4/G6/G7（`beat-gap`/`major-early`/`ep-fields`）+
  剧本 G3（`hook-open`）→ 本项目 `Beats.tags` 只标记「转折/峰值」，无权重与兑现追踪。
  **动作**：`Beats` 增补 `weight`（minor/major）与 `hookBeat` 外键。

### 1.3 剧本侧

- **大纲结构化**：shuohao `novel-outline` 输出 `outline.json` 带 8 道门
  （含 `crowd-plan` 三人以上同框必须标拆解方案、`risk-flag` 关键词扫描预警生成难点、
  `no-dialogue` 梗概必须是叙述体）→ 本项目大纲是自由 Markdown，无结构化约束。
  **动作**：大纲升级为 JSON，`outline_editor_page.dart` 改「结构化 + 门列表」双视图。
- **每场必须有一个动作节拍**：shuohao `novel-script` G6（`has-action`，「纯对白的场是广播剧」）
  → 本项目 `Beats.type` 有「动作」值但不强制。**动作**：新增 `ScriptGate`，纯对白场景提示（warn）。
- **动作描述与台词分离**：shuohao G7（`action-prose`，台词只进 `dialogue` 字段）→
  本项目 `Beats.content` 与 `Scenes.dialogue` 分离但无校验。
  **动作**：`ScriptGate` 扫 action 正文里是否出现「」引号。
- **说话人归属校验**：shuohao G2（`speaker`，说话人须在本场人物内或明确标 VO）→
  本项目 `Scenes.dialogue[].speaker` 无校验。**动作**：`ScriptGate.speakerCheck`。
- **集级钩子与悬念**：shuohao G4（`hook-cliff`，每集开场钩子与结尾悬念都要落在纸面）→
  本项目 `Scripts` 无对应列。**动作**：`Scripts` 增补 `hook` / `cliff`，改编 prompt 强制输出。

### 1.4 骨架/分镜侧

- **节拍认领覆盖率**：shuohao G1（`coverage`，剧本节拍被**恰好一次**、**按顺序**、连续认领）
  → 本项目 `Shots.beatRefs` 有引用，但不校验「恰好一次」与「顺序」。
  **动作**：新增 `SkeletonGate` 遍历全部 `Beats.id` 检查认领唯一性与顺序——
  这是「分镜漏拍剧情」的机械防线。
- **单分镜同框人数上限**：shuohao G6（`crowd`，`maxOnScreen` 可配，超了必须带拆解说明）
  → 本项目完全没有。**动作**：新增 `ShotGate.crowdCheck`，与 `crowd-plan` 呼应。
- **段号连号校验**：shuohao G8（`segment-id`，`E01-01` 格式、按顺序连号）→
  本项目 `Shots.globalSeq` 是自由字符串。**动作**：新增门，段号须匹配 `G\d{2}` 且批内连号。
- **景别/运镜词必须回落到提示词**：shuohao G9/G10（`size-phrase`/`camera-phrase`）检查
  景别中文词写进分镜图提示词、运镜用官方词表且出现在自己的 `[Shot k]` 段落 →
  本项目字段独立、提示词靠 `VideoPromptBuilder` 拼装但无回查。
  **动作**：新增门校验 `ShotFrames.shotSize` / `camera` 出现在最终 `prompt` 字符串里。
- **切段秒数下界**：shuohao G3/G4（`segment-cap`/`cut-length`）→ 本项目
  `SegmentBudget.maxSegmentMs` 只有上界。**动作**：增补 `minSegmentMs`（如 3000ms）+
  `under_limit` 校验码（过短的分镜反而节奏乱）。
- **提示词结构对账**：shuohao G11-G14（`h3-structure`/`h3-dialogue`/`h3-lang`/`h3-shot`）
  逐字对账切点时刻与说话人编号 → 本项目 `VideoPromptBuilder` 拼装式，无结构对账。
  **动作**：新增 `VideoPromptGate`，校验切点时刻与前一分镜秒数累计一致、`<d>` 块包含
  认领节拍的全部台词。
- **视频提示词禁角色名**：shuohao G15（`prompt-no-names`，视频侧不含角色名，分镜图侧直呼其名放行）
  → 本项目 `VideoPromptBuilder` 未做此区分。**动作**：新增门，仅视频侧扫角色名单。
- **分镜图提示词中文非空**：shuohao G13（`frame-prompt`）→ 本项目无此门。
  **动作**：`PromptGate` 增补 `frame_empty`（error）。

### 1.5 资产/图像侧

- **一致性锚点数量区间**：shuohao `novel-art` G1（`anchors`，每场景/道具 3-5 个锚点）→
  本项目 `AppearanceAnchor` 是 JSON 但无数量校验。**动作**：`PromptGate` 增补 `anchor_count`。
- **光照状态必落提示词**：shuohao G2（`lighting`）→ 本项目 `Assets.prompt` 不强制含光照词。
  **动作**：门扫 `prompt` 是否含光照词表。
- **道具状态/尺度参照/白背景**：shuohao G7-G9（`prop-states`/`prop-scale`/`prop-white`）
  → 本项目 `PromptGate.prop_has_hand` 只查手部。**动作**：三门合并进同一 `PromptGate`。
- **角色设定图分区版式**：shuohao 明写「16:9 分三区：左侧约 34% 证件照式半身像、右上全身
  三视图、右下关键细节特写条，白底方便抠图」→ 本项目 `boardLayout` 只有四视图/主视图/2x2。
  **动作**：新增「分区」版式，对齐抠图需求；出图后自动存一份透明背景版本。
- **同槽位多版本参考图**：AIComicBuilder `0050_add_shot_assets.sql` 的 `shot_assets` 表
  （`shot_id + type + sequence_in_type + asset_version + is_active`）支持单镜头并存多版本参考图
  → 本项目 `AssetRefs` 是纯引用表（`shot_id + asset_id + role + order`），无版本维度。
  **动作**：`AssetRefs` 增补 `version` / `isActive`，支持「分镜图 A/B 参考图」对比选优。

### 1.7 提示词治理侧

- **提示词版本历史**：AIComicBuilder `prompt_templates` + `prompt_versions`（每次修改存一版）

- **提示词 A/B 测试**：AIComicBuilder `0047_add_prompt_ab_tests`（`variant_a`/`variant_b`/

### 1.8 项目侧

- **项目/集级视觉调板**：AIComicBuilder `0029_add_project_color_palette` +
  `0030_add_episode_color_palette` → 本项目 `Scripts.artStyle` 只有单一风格字段。
  **动作**：`Scripts` 增补 `colorPalette` JSON 数组，`AssetService` 与 `VideoPromptBuilder`
  拼进提示词。
- **多比例支持**：AIComicBuilder 支持 16:9 / 9:16 / 1:1 / 自适应，首尾帧与视频统一比例 →
  本项目 M14 把 `Scripts.aspectRatio` 当死字段删掉了，成片固定 1280x720。
  **动作**：竖屏是短视频平台的真实需求，复活 `aspectRatio` 并透传给供应商。
- **多风格自适应**：AIComicBuilder 自动识别剧本风格，四视图与首尾帧匹配对应风格 →
  本项目 `artStyle` 是单一字段。**动作**：升级为「风格族 + 具体风格」二层，
  `PromptGate.style_conflict` 已有互斥族校验基础。
  **状态（M21 已落地）**：`Scripts.artStyle` 改为存画风短名（默认 `null`），

- **供应商多账号**：AIComicBuilder 支持同一 supplier 多账号轮换 → 本项目 `ProviderConfigs`
  一个 `id` 一个 `baseUrl`。**动作**：拆成「配置模板 + 账号实例」两表，`SecureKeyStore` 存多 Key。
- **场景参考帧模式**：AIComicBuilder `0005_add_scene_ref_frame`（首尾帧模式的替代）→
  本项目只有「分镜图 + 视频」两种，首帧=分镜图。**动作**：`ShotFrames` 增补 `isSceneRef`。
- **视频脚本与提示词分离**：AIComicBuilder `0006_add_video_script` 给 `shots` 加
  `video_script`（自然语言）与 `prompt`（结构化）分离 → 本项目只有最终 `prompt`。
  **动作**：`Shots` 增补 `videoScript`，`VideoPromptBuilder` 由它转结构化。
- **集描述与关键词**：AIComicBuilder `0011_add_episode_description_keywords` →
  本项目 `Scripts` 有 `episodeNo` 但无描述/关键词。**动作**：增补两列，改编 prompt 强制输出。
- **导入日志**：AIComicBuilder `0012_add_import_logs`（`step + status + message + metadata`）
  跟踪剧本导入过程 → 本项目 `ChapterImport` 是一次性解析，失败直接抛错，过程不可追溯。
  **动作**：新增 `ImportLogs` 表，`ChapterImport` 每步（读取/编码探测/标题提取/内容切片）写一行。
- **整集分镜回滚**：AIComicBuilder `0007_add_storyboard_versions` + `shots.version_id` 外键 →
  本项目 `ShotRevisions` 按 `kind` 拆分，「整集某一版」无法作为一个整体回滚。
  **动作**：`ShotRevisions` 增补 `versionGroup`，UI 支持整集回滚。

### 1.9 Agent 协作侧

- **项目 × Agent 绑定**：AIComicBuilder `0052_add_agents` + `0053_add_agent_platform` 的

### 1.10 质量门基础设施

- **质量门历史日志**：shuohao `gateLogEntries` + `summarizeGateLog` 每次 `validate` 追加到
  `.gates.jsonl`，可事后统计「模型最常违反哪条规则」+「哪些门从没响过」→ 本项目
  `GenerationAttempts` 台账只记「消耗算力的调用」，不含未消耗算力的校验。
  **动作**：新增 `GateLogs` 表（`subjectType/subjectId/gateId/ok/detail/createdAt`），
  `GateIssueList` 的「记一次」按钮写这里；报表页出「最常响 / 从没响」两个榜单。
  这是所有门的元数据基础设施，先有表后面每个门都受益。

## 4. 按投入产出比排序的 Top 5

1. **提示词版本历史表**（1.7）：`PromptOverrideVersions` 表 + DAO 在 `upsert` 前插一版。
   改动集中在 `prompt_override_dao.dart` 与 `prompt_override_page.dart`，用户改坏了能回退，
   风险极低，收益直接。
2. **分镜质量门三条**（1.4）：同框人数上限、段号连号、视频提示词禁角色名。
   三条纯函数门各 50-100 行，`listTransitionIssues` 已有范式可复用。
   这是「模型画出第七个人」这类用户抱怨最多的问题的机械防线。
3. **节拍认领覆盖率门**（1.4）：校验剧本节拍被恰好一次、按顺序认领。
   这是「分镜漏拍剧情」的唯一机械防线，且 `Shots.beatRefs` 已有数据，只需遍历校验。
4. **音色提示词 + 角色关系历史表**（1.1）：`CharacterSpec.voiceDesign` + `CharacterRelations`
   表 + 一份 skill + Settler 一处调用，投入小，对长篇连贯性提升立竿见影
   （角色换音色、关系反转都是常见需求）。
5. **质量门历史日志表**（1.10）：`GateLogs` 表 + 「记一次」按钮接线，
   让用户看到「哪条门最常响、哪条门从没响」，反过来指导提示词调优。
