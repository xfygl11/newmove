# 02 · 系统架构设计

> 本文档定义 App 的总体架构、模块划分、数据模型与 AI 集成方式。技术栈默认按 **Flutter** 描述，若改用 Kotlin/RN，架构思想不变，仅实现语言调整。

---

## 1. 总体架构（分层）

```text
┌────────────────────────────────────────────────────────────┐
│                        UI 层（Feature 页面）                 │
│  项目列表 / 小说编辑器 / 剧本编辑器 / 骨架视图 / 资产画廊 /    │
│  分镜列表 / 镜头预览 / 模型供应商配置 / 生成进度               │
└───────────────────────────┬────────────────────────────────┘
                            │ 事件 / 状态（Riverpod）
┌───────────────────────────▼────────────────────────────────┐
│                    应用服务层（UseCase / Service）            │
│  NovelService  ScriptService  SkeletonService  AssetService  │
│  ShotService   GenerationQueue   AuthConfig(供应商配置)      │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                 Pipeline 编排层（核心引擎）                   │
│  StageOrchestrator（阶段状态机）                              │
│  Agents：Planner/Writer/Reviewer/Adapter/Director/Asset/Shot │
│  Skills 注册表（Prompt 模板与规则，借鉴 Toonflow）             │
│  TruthFiles 管理器（借鉴 InkOS）                              │
└───────────┬──────────────────────────────┬─────────────────┘
            │                              │
┌───────────▼───────────────┐  ┌───────────▼───────────────┐
│      数据层（Repository）    │  │    AI 接入层（Adapter）     │
│  SQLite(Drift) + 文件目录   │  │  LlmProviderAdapter        │
│  Novel/Script/Asset/Shot   │  │  ImageProviderAdapter       │
│  TruthFile 持久化           │  │  VideoProviderAdapter       │
└────────────────────────────┘  │  (OpenAI 兼容 + 异步任务)    │
                                └────────────────────────────┘
```

**核心原则：**
- UI 不直接调 AI，一切生成动作经 Pipeline 编排层，保证状态可追踪、可断点续跑、可人工介入。
- 数据层只做持久化，不含业务规则；业务规则集中在服务层与 Agent Prompt 中。
- AI 接入层是纯协议适配，不感知业务语义。

## 2. 模块划分

| 模块 | 职责 | 借鉴来源 |
|---|---|---|
| `project` | 项目/作品管理（元数据、封面、状态） | Toonflow 项目 |
| `novel` | AI 写小说：设定/大纲/章节/审校 | InkOS |
| `script` | 小说 → 动漫剧本改编 | Toonflow sourceAndScript + screenAdaptation |
| `skeleton` | 剧本骨架提取：节拍/分段/时长/出镜状态 | Toonflow PART A A2–A4 |
| `asset` | 动漫资产图片生成与管理 | Toonflow assets.md |
| `shot` | 分镜与镜头生成（图/视频） | Toonflow PART A A5–A9 |
| `pipeline` | 阶段编排、Agent 调度、状态机 | Toonflow 三层 Agent |
| `agent` | 各专职 Agent 定义与 Skill 注册 | Toonflow skills/teams + InkOS agents |
| `provider` | 模型供应商适配（LLM/图/视频） | Toonflow providers |
| `storage` | SQLite 数据层 + 本地文件管理 | — |

## 3. 数据模型（核心实体）

> 存储：Drift（SQLite）+ 应用私有目录文件。资产图片/视频文件存文件系统，元数据与路径存 DB。

### 3.1 实体关系总览

```text
Project (1) ──< NovelBook (1) ──< Chapter (N)
                        │
                        └──< TruthFile (7 类状态文件)
NovelBook (1) ──< Script (1) ──< Scene (N) ──< Beat (N)  [节拍]
Script (1) ──< Asset (N)      [角色/场景/道具]
Script (1) ──< Shot (N) ──< ShotFrame (N)  [镜头内分镜画面]
Shot (N) ──< AssetRef (N)     [镜头引用的资产/参考图]
```

### 3.2 关键实体字段

#### Project（项目）

```text
id, name, coverPath, genre, description, status, createdAt, updatedAt
```

#### NovelBook（小说书）

```text
id, projectId, title, genre, styleGuide, premise(故事命题), status
```

#### Chapter（章节）

```text
id, bookId, seq, title, summary, content(markdown), wordCount,
status(草稿/审校中/定稿), revision, createdAt, updatedAt
```

#### TruthFile（真相状态，借鉴 InkOS 权威 JSON 状态机制）

> InkOS 实际机制为 `story/state/*.json` 权威状态（SPO 事实三元组带章节有效期、伏笔钩子五状态、章节摘要）+ `story/*.md` 人类可读投影；本项目将其适配为 7 类本地状态表。

```text
id, bookId, kind(世界事实/角色矩阵/资源与道具/伏笔钩子/章节摘要/作者意图/当前焦点),
content(json), revision, updatedAt
```

- `世界事实`：SPO 三元组（subject/predicate/object + validFromChapter/validUntilChapter/sourceChapter）。
- `伏笔钩子`：状态 open/progressing/deferred/resolved/superseded + expectedPayoff。
- 投影视角（如角色矩阵的 Markdown 呈现）由查询时渲染，不单独落表。

#### Script（剧本）

```text
id, bookId, title, version, fidelityMode(忠实度), artStyle, aspectRatio,
language, status(草案/定稿), content(json 或结构化)
```

#### Scene（场）

```text
id, scriptId, seq, location, time, characters(json), summary,
action, startState, endState, transition
```

#### Beat（节拍，借鉴 Toonflow A2 原子节拍）

```text
id, sceneId, seq, type(对白/动作/反应/信息/过渡/留白),
who, content, object(作用对象), sourceRef(源剧情位置 E##),
estDurationMs, tags(转折/峰值/信息增量/决策/沉默)
```

#### Asset（资产）

```text
id, scriptId, type(角色/场景/道具), name, stableId(稳定标识),
variantOf(变体父资产), appearanceAnchor(外观锚点 json),
boardLayout(四视图/主视图/2x2), prompt, imagePath, status(待生成/生成中/待验收/已采用)
```

#### Shot（镜头/片段，借鉴 Toonflow A3 分段）

```text
id, scriptId, globalSeq(G01), batch, modelVersion(2.0/2.5),
durationMs, globalTimeRange, shotType, sceneId,
prompt(最终生成提示词), status, outputPath, outputType(image/video)
```

#### ShotFrame（镜头内画面，借鉴 A4 出镜状态）

```text
id, shotId, seq, timeRange, subject, shotSize(景别), angle(角度),
camera, blocking(站位), performance(表演), dialogue(台词原文)
```

#### AssetRef（镜头-资产引用）

```text
id, shotId, assetId, role(角色参考/场景参考/道具参考/仅站位), order
```

## 4. AI 接入层（ProviderAdapter）

### 4.1 供应商配置模型

参考 Toonflow `customProviders` 的统一结构（`{ id, label, apiUrl, apiKey, protocol, models }`，见 `apps/web/src/stores/settings.ts`），App 按用途分三组管理，用户自配：

```json
{
  "llmProviders": [
    { "id": "deepseek", "label": "DeepSeek", "baseUrl": "https://api.deepseek.com",
      "apiKey": "sk-***", "protocol": "openai-completions",
      "models": [{ "id": "deepseek-chat", "label": "DeepSeek Chat" }] }
  ],
  "imageProviders": [
    { "id": "gptimage", "label": "GPT-Image", "baseUrl": "...", "apiKey": "sk-***",
      "protocol": "openai-images", "models": [{ "id": "gpt-image-1" }] }
  ],
  "videoProviders": [
    { "id": "seedance", "label": "Seedance", "baseUrl": "...", "apiKey": "sk-***",
      "protocol": "async-task", "models": [{ "id": "seedance-2.0" }] }
  ]
}
```

> 分三组是本项目的扩展（Toonflow 为单一 provider 列表 + protocol 字段区分），便于移动端配置页按 LLM/图/视频 分区展示与连通测试。

### 4.2 协议适配

| 能力 | 协议 | 说明 |
|---|---|---|
| LLM 文本 | OpenAI `/v1/chat/completions` + SSE | 流式输出、JSON mode、多模态参考（图片 base64） |
| 文生图 | OpenAI Images 兼容 或 异步任务 | 同步返回 URL 或 提交 job 后轮询 |
| 图生图 | 同上 + 参考图 base64/URL | 用于资产变体、角色一致性 |
| 文/图生视频 | 异步任务（提交 → 轮询 → 回填） | 借鉴 Seedance，App 内做任务队列 |

### 4.3 关键设计：Agent 与 Prompt 分离

- **Skill = Prompt 模板 + 规则**（借鉴 Toonflow 的 Markdown skills），存储在 `skills/` 目录，随 App 打包。
- **Agent = 一个「系统提示词 + 可用工具 + 模型配置」的封装**。
- Pipeline 每阶段实例化对应 Agent，注入当前结构化数据作为上下文，调用 LLM，解析 JSON 结果写回 DB。

## 5. Pipeline 编排层（核心引擎）

### 5.1 阶段状态机

```text
[创意] → A写作 → B改编 → C骨架 → D资产 → E镜头
   │        │       │       │       │        │
   └── 每个阶段：待执行 → 执行中 → 待人工确认 → 已确认/已修订
                                    │
                                    └── 可回溯到上一阶段重跑
```

- 每个阶段产物**落库持久化**，支持断点续跑。
- 阶段切换默认**需人工确认**（可配置为自动连跑）。
- 任何阶段失败/超时，记录原因，可重试，不丢失已完成数据。

### 5.2 Agent 角色清单

| Agent | 阶段 | 借鉴 |
|---|---|---|
| Planner | A 写作规划 | InkOS Planner |
| Writer | A 章节写作 | InkOS Writer |
| Reviewer | A 审校 + C/E 监督 | InkOS 审稿 Agent/连续性审计员 + Toonflow reviewer |
| Adapter | B 剧本改编 | Toonflow screenAdaptation |
| Director | C 骨架 + E 镜头导演 | Toonflow PART A |
| AssetDesigner | D 资产设计 | Toonflow assets.md |
| Settler | A 状态固化 | InkOS Settler |

### 5.3 Truth Files 管理器（借鉴 InkOS）

- 每写完一章，Writer 产出正文，Settler 以「有证据的增量 delta」更新 7 类 TruthFile（对照 InkOS typed tool + 宿主校验原子落盘的机制，简化为本地事务写入）。
- Reviewer 审校时对照 TruthFile 检查一致性（OOC/时间线/伏笔/道具）。
- 写作下一章时，把 TruthFile 作为上下文注入（吸收 InkOS Composer 思想：只注入相关片段，记录本章实际注入的上下文，控制 token）。

## 6. 生成任务队列（镜头/资产）

- 图片/视频生成耗时且可能失败，统一走**本地任务队列**。
- 任务状态：`排队 → 提交 → 生成中 → 成功/失败 → 已采用/已废弃`。
- App 前台轮询；退到后台时暂停轮询，回前台恢复（移动端限制）。
- 每个任务记录：提示词、参数、供应商、耗时、费用（如可查询）、结果文件路径。

---

## 7. 本地存储与安全

- **SQLite**：Drift，存所有结构化元数据与 JSON 快照。
- **文件**：应用私有目录 `files/assets/`、`files/shots/`、`files/novel/`。
- **API Key 安全**：存 Android Keystore / flutter_secure_storage，不写入 DB 明文。
- **导出/备份**：支持导出项目为 zip（JSON + 图片/视频），可导入恢复。
