# 02 · 系统架构设计

> 本文档定义 App 的总体架构、模块划分、数据模型与 AI 集成方式。技术栈默认按 **Flutter** 描述，若改用 Kotlin/RN，架构思想不变，仅实现语言调整。

---

## 1. 总体架构（分层）

```text
┌────────────────────────────────────────────────────────────┐
│                        UI 层（Feature 页面）                 │
│  项目列表 / 小说编辑器 / 剧本编辑器 / 骨架视图 / 资产画廊 /    │
│  分镜列表 / 镜头预览 / 模型供应商配置 / 生成进度               │
└───────────────────────────┬────────────────────────────────┘
                            │ 事件 / 状态（Riverpod）
┌───────────────────────────▼────────────────────────────────┐
│                    应用服务层（UseCase / Service）            │
│  NovelService  ScriptService  SkeletonService  AssetService  │
│  ShotService   GenerationQueue   AuthConfig(供应商配置)      │
└───────────────────────────┬────────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────────┐
│                 Pipeline 编排层（核心引擎）                   │
│  StageOrchestrator（阶段状态机）                              │
│  Agents：Planner/Writer/Reviewer/Adapter/Director/Asset/Shot │
│  Skills 注册表（Prompt 模板与规则，借鉴 Toonflow）             │
│  TruthFiles 管理器（借鉴 InkOS）                              │
└───────────┬──────────────────────────────┬─────────────────┘
            │                              │
┌───────────▼───────────────┐  ┌───────────▼───────────────┐
│      数据层（Repository）    │  │    AI 接入层（Adapter）     │
│  SQLite(Drift) + 文件目录   │  │  LlmProviderAdapter        │
│  Novel/Script/Asset/Shot   │  │  ImageProviderAdapter       │
│  TruthFile 持久化           │  │  VideoProviderAdapter       │
└────────────────────────────┘  │  (OpenAI 兼容 + 异步任务)    │
                                └────────────────────────────┘
```

**核心原则：**
- UI 不直接调 AI，一切生成动作经 Pipeline 编排层，保证状态可追踪、可断点续跑、可人工介入。
- 数据层只做持久化，不含业务规则；业务规则集中在服务层与 Agent Prompt 中。
- AI 接入层是纯协议适配，不感知业务语义。

## 3. 数据模型（核心实体）

> 存储：Drift（SQLite）+ 应用私有目录文件。资产图片/视频文件存文件系统，元数据与路径存 DB。

### 3.1 实体关系总览

```text
Project (1) ──< NovelBook (1) ──< Chapter (N)
                        │
                        └──< TruthFile (7 类状态文件)
NovelBook (1) ──< Script (1) ──< Scene (N) ──< Beat (N)  [节拍]
Script (1) ──< Asset (N)      [角色/场景/道具]
Script (1) ──< Shot (N) ──< ShotFrame (N)  [镜头内分镜画面]
Shot (N) ──< AssetRef (N)     [镜头引用的资产/参考图]
```

### 3.2 关键实体字段

#### Project（项目）

```text
id, name, coverPath, genre, description, status, createdAt, updatedAt
```

#### NovelBook（小说书）

```text
id, projectId, title, genre, styleGuide, premise(故事命题), status
```

#### Chapter（章节）

```text
id, bookId, seq, title, summary, content(markdown), wordCount,
status(草稿/审校中/定稿), revision, createdAt, updatedAt
```

#### TruthFile（真相状态，借鉴 InkOS 权威 JSON 状态机制）

> InkOS 实际机制为 `story/state/*.json` 权威状态（SPO 事实三元组带章节有效期、伏笔钩子五状态、章节摘要）+ `story/*.md` 人类可读投影；本项目将其适配为 7 类本地状态表。

```text
id, bookId, kind(世界事实/角色矩阵/资源与道具/伏笔钩子/章节摘要/作者意图/当前焦点),
content(json), revision, updatedAt
```

- `世界事实`：SPO 三元组（subject/predicate/object + validFromChapter/validUntilChapter/sourceChapter）。
- `伏笔钩子`：状态 open/progressing/deferred/resolved/superseded + expectedPayoff。
- 投影视角（如角色矩阵的 Markdown 呈现）由查询时渲染，不单独落表。

#### Script（剧本）

```text
id, bookId, title, version, fidelityMode(忠实度), artStyle, aspectRatio,
language, status(草案/定稿), content(json 或结构化)
```

#### Scene（场）

```text
id, scriptId, seq, location, time, characters(json), summary,
action, startState, endState, transition
```

#### Beat（节拍，借鉴 Toonflow A2 原子节拍）

```text
id, sceneId, seq, type(对白/动作/反应/信息/过渡/留白),
who, content, object(作用对象), sourceRef(源剧情位置 E##),
estDurationMs, tags(转折/峰值/信息增量/决策/沉默)
```

#### Asset（资产）

```text
id, scriptId, type(角色/场景/道具), name, stableId(稳定标识),
variantOf(变体父资产), appearanceAnchor(外观锚点 json),
boardLayout(四视图/主视图/2x2), prompt, imagePath, status(待生成/生成中/待验收/已采用)
```

#### Shot（镜头/片段，借鉴 Toonflow A3 分段）

```text
id, scriptId, globalSeq(G01), batch, modelVersion(2.0/2.5),
durationMs, globalTimeRange, shotType, sceneId,
prompt(最终生成提示词), status, outputPath, outputType(image/video)
```

#### ShotFrame（镜头内画面，借鉴 A4 出镜状态）

```text
id, shotId, seq, timeRange, subject, shotSize(景别), angle(角度),
camera, blocking(站位), performance(表演), dialogue(台词原文)
```

#### AssetRef（镜头-资产引用）

```text
id, shotId, assetId, role(角色参考/场景参考/道具参考/仅站位), order
```

## 4. AI 接入层（ProviderAdapter）

### 4.1 供应商配置模型

参考 Toonflow `customProviders` 的统一结构（`{ id, label, apiUrl, apiKey, protocol, models }`，见 `apps/web/src/stores/settings.ts`），App 按用途分三组管理，用户自配：

```json
{
  "llmProviders": [
    { "id": "deepseek", "label": "DeepSeek", "baseUrl": "https://api.deepseek.com",
      "apiKey": "sk-***", "protocol": "openai-completions",
      "models": [{ "id": "deepseek-chat", "label": "DeepSeek Chat" }] }
  ],
  "imageProviders": [
    { "id": "gptimage", "label": "GPT-Image", "baseUrl": "...", "apiKey": "sk-***",
      "protocol": "openai-images", "models": [{ "id": "gpt-image-1" }] }
  ],
  "videoProviders": [
    { "id": "seedance", "label": "Seedance", "baseUrl": "...", "apiKey": "sk-***",
      "protocol": "async-task", "models": [{ "id": "seedance-2.0" }] }
  ]
}
```

> 分三组是本项目的扩展（Toonflow 为单一 provider 列表 + protocol 字段区分），便于移动端配置页按 LLM/图/视频 分区展示与连通测试。

### 4.1.1 一键获取模型（借鉴 Toonflow `fetchProviderModels` / `refreshMediaProviderModels`）

Toonflow 的拉取实现（`apps/server/src/utils/ai/models.ts:11-45`）：URL 取 `apiUrl`，pathname 为 `/` 时补成 `/v1`，再拼 `/models`；请求头 `Accept: application/json`，鉴权默认 `Bearer`，anthropic 协议改用 `x-api-key` + `anthropic-version: 2023-06-01` + `limit=1000`，用 `has_more/last_id → after_id` 游标分页；响应 `{ data: [{ id, display_name?|displayName?, inputTokenLimit?, outputTokenLimit? }], has_more?, last_id? }`；`label = display_name || displayName || id`；30s 超时。

媒体模型拉取（`apps/server/src/utils/media/provider.ts:282-308`）：请求供应商 `modelsUrl`（可带 `?type=image|video|audio` 过滤）+ Bearer；响应 `{ data: [...] }` 上限 2000；模型 type 解析顺序 `model.type → URL type 参数 → 同 id 旧模型 type`；同 id 沿用旧参数（只有 ID 的新模型不猜能力）；替换时只覆盖本次返回的 type 集合，其余 type 的旧模型保留。

App 采用的简化适配：

| 供应商组 | 端点 | 鉴权 | 响应字段映射 |
|---|---|---|---|
| LLM | `{baseUrl}/models`（pathname `/` 先补 `/v1`） | `Bearer`（本项目暂无 anthropic 组，保留分支） | `id`；`label=display_name‖displayName‖name‖id`；`contextWindow=inputTokenLimit`、`maxOutputTokens=outputTokenLimit` |
| 图片/视频 | `{baseUrl}/models?type=image|video` | `Bearer` | 同上 + `type`（同 Toonflow 三级解析） |

- 拉取结果**合并**进现有模型列表：同 id 保留既有勾选态与能力字段，仅补 label；新模型默认**未勾选**，由用户勾选启用。
- 视频供应商 `modelsUrl` 未显式配置时默认取 `{baseUrl}/models?type=video`；带 type 参数可过滤无关模型（借鉴 Toonflow mediaProvider.modelsUrl 设计）。

### 4.1.2 模型能力字段与勾选态（借鉴 Toonflow `MediaModel`）

Toonflow `MediaModel`（`packages/toolScaffold/src/runtime.ts:74-86`）携带能力字段供节点 UI 动态收敛选项：`imageSizes`、`imageRatios`（图片可选尺寸/画幅）、`durationResolutionMap`（视频 时长↔分辨率 合法组合）、`audio?: boolean | "optional"`、`mode`（参考图模式词表）。本项目 `ProviderModel` 相应扩展：

```json
{ "id": "seedance-2.0", "label": "Seedance 2.0", "enabled": true,
  "imageSizes": ["1024x1024", "2048x2048"], "imageRatios": ["16:9", "9:16", "1:1"],
  "durationResolutions": [{ "duration": [4, 6, 8, 10], "resolution": ["720p", "1080p"] }],
  "audio": "optional", "contextWindow": 128000, "maxOutputTokens": 8192 }
```

- `enabled`（勾选态）：序列化缺省视为 `true`（兼容旧数据）；**生成链路只使用勾选模型**（`activeLlmProvider`/`activeImageProvider`/`activeVideoProvider` 过滤 `enabled=false`）。
- 能力字段全部可选；缺省时 UI 落回通用词表（画幅 5 项、分辨率 720p/1080p、时长 4–15s），即能力未知时行为与现状一致。
- 拉取到的模型只有 ID 时（新模型）不猜测能力，能力字段留空沿用默认词表（对齐 Toonflow「同 id 沿用旧参数，新模型不猜能力」）。

**M8 扩展（`ModelPresets` + 能力 getter）**：

- `ProviderModel` 新增 `videoModes`（`text`/`singleImage`/`startEndRequired`/`endFrameOptional`/`startFrameOptional`/`imageReference`/`videoReference`/`audioReference`）与 `maxImageRefs`（默认 9）。
- 能力 getter：`supportedDurations`（时长并集去重升序）、`resolutionsFor(int sec)`（按时长命中组合并集）、`supportsStartFrame`（`videoModes` 含 `startFrameOptional`/`endFrameOptional`/`startEndRequired`）、音频三态 `audioRequired`/`audioDisabled`/`audioOptional`。
- `ModelPresets.apply/applyAll`：seedance 2.5/2.0、wan-3、minimax、kling、seedream 系列按「仅补空字段、不覆盖用户已填」补全；`ModelFetcher.mergeFetched` 拉取新模型时套预设。
- 参数归一化：`ProviderModel.normalizeDuration(int)`（最接近合法值，无能力返回原值）、`normalizeResolution(int, String)`（按时长并集，无匹配取首个，无能力返回原值），供镜头详情页模型切换回落。
- DB schemaVersion 4→5：`VideoTasks` 增 `outputPath`、`ProviderConfigs` 增 `readme`（供应商说明，卡片副标题显示）。
- 首帧通道：`VideoProviderAdapter.submit` 新增 `firstFramePath` 与 `maxImageRefs` 参数；`ShotService.submitVideo` 按 `params.useFirstFrame` 将分镜图拆作 `firstFramePath`（`role:'first_frame'`，占 1 个参考位），余图按 `maxImageRefs` 取上限作 `reference_image`；`useFirstFrame` 仅 `supportsStartFrame` 时显示。

### 4.2 协议适配

| 能力 | 协议 | 说明 |
|---|---|---|
| LLM 文本 | `openai-chat`：`POST {base}/chat/completions` + SSE | 流式输出、JSON mode、多模态参考（图片 base64） |
| 文生图 | `openai-images`：`POST {base}/images/generations` | 同步返回 URL 或 b64_json；支持参考图（`imageToImageMulti`） |
| 文/图生视频 | `async-task`：`POST {base}/video/generateVideo` + `POST {base}/video/getVideoStatus` | 异步任务三步流（提交→轮询→回填），借鉴 Seedance/Toonflow |
| 文/图生视频 | `openai-videos`：`POST {base}/videos` + `GET {host}/agnesapi?video_id=&model_name=` | Agnes AI 专有协议；轮询端点在 host 根路径（去掉 `/v1` 前缀）；由 `ProviderConfig.protocol` 字段路由 |
| 模型列表获取 | `{baseUrl}/models` | 见 §4.1.1；LLM 直接拉取，媒体组带 `?type=` 过滤 |

**协议路由机制**：`ProviderConfig.protocol` 字段（`openai-chat` / `openai-images` / `async-task` / `openai-videos`）由 UI 下拉选定，`ShotService.submitVideo` / `pollVideoTask` 透传给 `VideoProviderAdapter.submit(protocol:)` / `poll(protocol:, model:)`，适配器内按协议分支处理。`ActiveVideo.protocol` 字段从供应商配置中读出，`shot_service.dart` 调用时传递。

**Agnes AI 一键预设**（`lib/features/provider_config/agnes_presets.dart`）：

设置页「一键添加 Agnes 预设」按钮创建 3 个供应商条目（API Key 存系统 Keystore，不进 DB）：

| 供应商 ID | 分组 | 协议 | 模型 | 能力参数 |
|---|---|---|---|---|
| `agnes-llm` | `llm` | `openai-chat` | `agnes-2.5-flash` | contextWindow 512000，maxOutputTokens 65536 |
| `agnes-image` | `image` | `openai-images` | `agnes-image-2.5-flash` | imageSizes 1K–4K，8 种画幅 |
| `agnes-video` | `video` | `openai-videos` | `agnes-video-2.5` + `agnes-video-2.5-flash` | 4–12s；720P/1080P/1K/2K；参考图上限 8（2.5）/ 5（flash）；首尾帧模式 |

Base URL 固定中国服务：`https://apihub.agnes-ai.cn/v1`。

### 4.3 关键设计：Agent 与 Prompt 分离

- **Skill = Prompt 模板 + 规则**（借鉴 Toonflow 的 Markdown skills），存储在 `skills/` 目录，随 App 打包。
- **Agent = 一个「系统提示词 + 可用工具 + 模型配置」的封装**。
- Pipeline 每阶段实例化对应 Agent，注入当前结构化数据作为上下文，调用 LLM，解析 JSON 结果写回 DB。

## 5. Pipeline 编排层（核心引擎）

### 5.1 阶段状态机

```text
[创意] → A写作 → B改编 → C骨架 → D资产 → E镜头
   │        │       │       │       │        │
   └── 每个阶段：待执行 → 执行中 → 待人工确认 → 已确认/已修订
                                    │
                                    └── 可回溯到上一阶段重跑
```

- 每个阶段产物**落库持久化**，支持断点续跑。
- 阶段切换默认**需人工确认**（可配置为自动连跑）。
- 任何阶段失败/超时，记录原因，可重试，不丢失已完成数据。

### 5.2 Agent 角色清单

| Agent | 阶段 | 借鉴 |
|---|---|---|
| Planner | A 写作规划 | InkOS Planner |
| Writer | A 章节写作 | InkOS Writer |
| Reviewer | A 审校 + C/E 监督 | InkOS 审稿 Agent/连续性审计员 + Toonflow reviewer |
| Adapter | B 剧本改编 | Toonflow screenAdaptation |
| Director | C 骨架 + E 镜头导演 | Toonflow PART A |
| AssetDesigner | D 资产设计 | Toonflow assets.md |
| Settler | A 状态固化 | InkOS Settler |

### 5.3 Truth Files 管理器（借鉴 InkOS）

- 每写完一章，Writer 产出正文，Settler 以「有证据的增量 delta」更新 7 类 TruthFile（对照 InkOS typed tool + 宿主校验原子落盘的机制，简化为本地事务写入）。
- Reviewer 审校时对照 TruthFile 检查一致性（OOC/时间线/伏笔/道具）。
- 写作下一章时，把 TruthFile 作为上下文注入（吸收 InkOS Composer 思想：只注入相关片段，记录本章实际注入的上下文，控制 token）。

## 6. 生成任务队列（镜头/资产）

- 图片/视频生成耗时且可能失败，统一走**本地任务队列**。
- 任务状态：`排队 → 提交 → 生成中 → 成功/失败 → 已采用/已废弃`。
- App 前台轮询；退到后台时暂停轮询，回前台恢复（移动端限制）。
- 每个任务记录：提示词、参数、供应商、耗时、费用（如可查询）、结果文件路径。

## 6.1 M10 补齐功能说明

### 大纲独立编辑（P0-1）

`OutlineEditorPage`（`lib/features/novel/outline_editor_page.dart`）：逐章目标卡片（标题 + 明细），解析/序列化 Markdown 大纲（「第 N 章」格式），写回 `book.outline`。支持增删章节、按序号重排。路由 `/novel/:projectId/outline`；入口在设定工坊大纲行 + 书架页。

### 角色矩阵管理（P0-2）

`CharacterManagerPage`（`lib/features/novel/character_manager_page.dart`）：角色增删改（姓名/定位/目标/状态/关系），写回 `character_matrix` TruthFile。与 Settler 定稿固化共用同一存储，手工编辑后定稿按名字合并（同名覆盖字段，新名追加）。路由 `/novel/:projectId/characters`；入口在设定工坊角色矩阵 Tab + 书架页。

### 审校定位（P0-3）

`ChapterEditorPage` 中 `_IssueCard` 加「定位」按钮，在正文中搜索 `issue.location` 关键词并选中 + 滚动；`_BottomBar` 新增实时字数显示（500ms 定时器驱动，避免每次按键重排整页）。

### 项目改名/删除（P0-4）

`_ProjectCard` 长按弹菜单（编辑/导出备份/删除），支持 `replaceProject`/`deleteProject`。

### 批量生成取消（P1-7）

`GenerationCancelToken`（`shot_service.dart`）：`generateSelected` 接受 `cancelToken` 参数，循环中检查 `cancelled` 并提前终止，返回 `ShotBatchResult.cancelled/pending`。`shot_list_page` 生成中显示「取消」按钮。

### 章节删除（P1-9）

`_ChapterTile`（`novel_shelf_page.dart`）改为 `ConsumerWidget`，长按弹菜单支持 `deleteChapter`。

## 6.2 M11 P2 功能说明

### 全库备份（P2-10）

`BackupService.exportAll()` 导出所有项目（books/chapters/truthFiles/scripts/scenes/beats/assets/shots/shotFrames/assetRefs/videoTasks/scriptRevisions）+ 供应商配置 + 被引用媒体文件，打包为单个 zip（`scope: full`，`projects` 列表字段）。`importProject` 兼容全库包与单项目包：全库包按原始 `projectId` 映射链重写 books→chapters→... 外键；单项目包行为不变。UI 入口：项目页 AppBar 备份菜单「导出全部项目」。

### 导入冲突检测（P2-11）

## 6.4 M13 健壮性约定

### 宽容 JSON 解析（`lib/core/json_values.dart`）

所有解析 AI 输出 / 落库 JSON 的模型统一使用本文件的取值函数，**禁止直接对外部数据用 `as` 强转**：

| 函数 | 行为 |
|---|---|
| `jsonString(v, [fallback=''])` | null → fallback，其余 `toString()` |
| `jsonStringOrNull(v)` | null 保持 null（保留 `String?` 可空语义） |
| `jsonInt(v, [fallback=0])` | int / num 截断 / 可 parse 字符串，其余 fallback |
| `jsonBool(v, [fallback=false])` | bool / 非零 num / `"true"\|"yes"\|"1"` 等字符串 |
| `jsonList(v)` | 非 List 返回空 List |
| `jsonMap(v)` | 非 Map 返回空 Map |

原因：LLM 输出常见类型漂移（数字写成字符串 `"seq":"1"`、布尔写成 `"true"`、id 写成数值），`as int?` / `as String?` 会抛 `TypeError`，导致整段生成结果解析失败。已覆盖 script / skeleton / asset / shot / novel / provider_config 各模型与解析点。

### 网络层解析约定

- 供应商响应一律先做类型守卫（`is List` / `is Map`）再取字段，不依赖 `as` 强转。
- SSE 流用 `utf8.decode(bytes, allowMalformed: true)`，畸形字节降级替换而非中断整条流。
- 错误提示拼接后截断必须按实际长度判断（`len < N ? s : s.substring(0, N)`），直接 `substring(0, N)` 在短字符串上抛 `RangeError`。

### 列表页数据加载约定

读取异步数据的页面统一在 `initState` 加载一次，配 `_loading` / `_error` / `_reload` 状态；**禁止**在 `build` 里构造 `FutureBuilder(future: _load())`（每次重建都会重新发起请求，且在 build 中产生副作用赋值）。

### LLM 回复的 JSON 剥离（`extractJsonObject`）

Agent 剥 JSON 包裹统一使用 `json_values.dart` 的 `extractJsonObject(reply)`，不各自复制实现（5 个 agent 共用一份）：

1. 支持 ```` ```json ```` 代码块包裹，也支持前后夹杂解释文字。
2. 整段解析失败时回退取「第一个 `{` 到最后一个 `}`」的区段再解析。
3. 仍失败**抛 `FormatException`**，绝不返回空 Map。

理由：骨架提取等服务是「删旧数据 → 插入新数据」，空 Map 会静默清空结果；抛异常既保护数据，又给出可读错误原因（"AI 返回内容不是有效 JSON，请重试"）。

### await 后的 UI 操作守卫

所有 `_toast` 类方法首行必须是 `if (!mounted) return;`。长耗时 AI 调用期间用户可能已离开页面，`showSnackBar` 会抛 "Looking up a deactivated widget's ancestor is unsafe"。同理适用于 `Navigator` / `showDialog` / `TextEditingController` 持有等任何依赖 `BuildContext` 的操作。

### 用户文件落盘的路径校验（防 zip slip）

任何把用户提供的压缩包条目名 / 文件名拼进落盘路径的代码，都必须走 `BackupService._resolveMediaPath` 式的校验：

- 拒绝绝对路径（含 Windows 盘符 `C:\`）；
- 拒绝 `.` / `..` / 空路径段；
- 解析后再校验绝对路径必须以目标目录为前缀（双重保险）。

不校验会导致构造的 zip（条目名 `../../x.png`）写出应用文档目录，越权污染文件系统。

## 6.5 数据完整性约定（M14）

**多表写必须原子。** 全库目前仅 `backup_service.dart:337` 一处事务，五个 service 的多表写全部裸写，中间态（JSON 解码抛错、磁盘满、进程被杀）会永久落库且无回滚。约定：

- 业务层不直接拼 `deleteByX` + 多次 `insert`，统一调 DAO 层「按父 id 重建」的复合方法，事务在 DAO 内。
- 复合方法内部严格按**最下游先行**的顺序删除：`VideoTasks → AssetRefs → ShotFrames → Shots → Beats → Scenes`。
- 表定义显式 `references(..., onDelete: KeyAction.cascade)`，配合迁移脚本升级约束；不得依赖 Drift 默认 `NO ACTION`。

**写顺序：先删后改，不可倒置。** `script_service.dart:110-118` 先 `updateRow` 写新正文、后 `_replaceScenes` 删场次，删除失败时正文已新版而场次仍旧版，骨架提取读到错位数据。凡「父行字段更新 + 子表重建」，一律先完成删除与插入、成功后再更新父行版本字段，整体单事务。

**删除入口必须级联。** `project_dao.dart:40` 的裸 delete 使「删除任何创建过书籍的项目」必然抛 `FOREIGN KEY constraint failed`。统一走 `deleteProjectCascade`：事务内按拓扑序清理全部表并清媒体目录，任何实体的删除入口（书籍 / 剧本 / 骨架 / 镜头 / 资产）不得遗漏下游表。

**TruthFile 写入需乐观锁。** `truth_file_store` 现为读改写，Settler 固化与用户手工编辑并发时后写者整表覆盖、前者修改静默丢失，`revision+1` 无法找回。约定以 `updatedAt` / `revision` 比对，不匹配则按 id 合并写入而非整表覆盖，合并放事务。

## 6.6 上下文预算约定（M14，借鉴 InkOS 权威分级）

**LLM 上下文必须预算内构造。** 现状全量拼接（`novel_service.dart:106-158, 231-237`、`script_service.dart:49-63`），`model_presets.dart` 的 `maxToken` 字段零使用方；长书累积到数十万字会 400 / 超时 / LLM 在截断上下文里输出错误 JSON 导致整章失败。

- 所有 prompt 构建走统一的 `ContextBudget`，按 `ProviderModel.maxToken` 折算预算（中文按 1 字 ≈ 1.5 token 估算）。
- TruthFile 标 `protection: protected | compressible`：用户意图 / 角色锁 / 规则永不压缩，章节摘要与旧章正文进入压缩池。
- 裁剪按优先级依次执行：伏笔只留 `open` / `progressing`，前情摘要只留近 N 章，角色矩阵只留本章出场角色。
- 裁剪必须可观测：被裁掉的条目写入日志与生成尝试台账，用户可查证上下文实际内容。

## 6.7 授权与执行分离（M14，借鉴 Toonflow）

**确认口径全局唯一。** 现状三个生成入口各写一套（`shot_detail_page.dart:445`、`shot_list_page.dart:233`、`asset_gallery_page.dart:95`），第三个不弹框且无视设置项。统一为 `ConfirmSheet`，固定展示：对象、数量、完整提示词、参数、参考文件与用途顺序、执行次数、费用预估（无法查询时明确「未知」）。

**授权后必须临执行复核。** 用户回复「确认」到实际调用之间数据可被并发修改。提交前重读当前数据并与授权快照比对，节点 / 提示词 / 模式 / 引用 / 数量任一变化则高亮差异重新授权；不得以「已确认」执行后来被改动的配置。读回与执行非原子操作，复核通过后若仍发生并发编辑，结果标注「依据待核实」。

**生成尝试需留台账。** 对齐 Toonflow 8 列：本地尝试标识、资产片段+节点、提示词快照、模型与完整参数、参考文件版本顺序及用途、调用前输出、授权范围与剩余次数、返回与实际文件。生成前保存快照，后续编辑不回写这次尝试；提示词版本与结果版本分开记录。

**阶段门纪律。** 确认简报 ≠ 确认剧本，确认资产 ≠ 验收生成结果，允许小样 ≠ 允许批量生产。所有涉及算力的提问必须写清方案与收费性质。

## 6.8 任务与状态约定（M14）

**取消语义完整。** `GenerationCancelToken` 需包装为 `dio.CancellationToken` 透传到适配器，每个 await 之后检查，而不只在 for 循环顶部判断。

**轮询需 per-task 超时且去重锁下沉。** `task_page.dart:111-125` 的串行 await 加 `_polling` 全局锁，任一请求半连接不返回则全局永久停刷。约定超时下沉到 `pollVideoTask` 内部按 taskId 串行化，避免任务页与镜头详情页并发轮询同一任务重复下载覆盖。

**状态需僵尸检测。** `shot_service.dart:616-628` 对网络异常保持「生成中」且无最大时长，供应商删任务后永久挂起。约定 `updatedAt` 超阈值（默认 60 分钟无变化）自动置失败并写 error；供应商配置变更后在途任务置失败。

**状态常量需统一且覆盖全枚举。** `ShotStatuses` 有 8 个状态，`task_page.dart:380-399` 的 `_TaskBadge` 只识别 2 个，6 个落灰色 default 导致「已完成」与「排队中」外观一致。抽统一 `StatusBadge` 组件与单一状态常量类，覆盖 Shot / VideoTask / Asset 三类实体全部枚举。

**状态迁移需幂等。** 重新导演（`shot_service.dart:147-154`）无条件写 `awaitingImage`，已出视频的镜头被降级而对应视频任务仍「已完成」。按当前状态幂等迁移：已确认 / 视频完成保持原状态，仅更新 prompt / 帧 / refs。

**文件校验需在读取前。** `shot_service.dart:721-722` 先 `readAsBytes()` 再判 100MB，超大文件先全量载入内存致 OOM。任何「读整个文件再校验」的模式改为先 `File.length()` 校验或流式分块。

## 6.9 命令与外部工具调用约定（M14）

**不得把用户可控文本拼进命令串。** `shot_compose_service.dart:52` 把剧本标题（`script_detail_page.dart:247`）拼进 FFmpeg 命令串，标题含 `"` 时输出路径可控，含 `/` 时目录不存在直接失败。约定：

- 文件名白名单过滤（`[^\w\-]` 替换为 `_`），输出路径由服务内部生成，调用方不指定。
- 用 `executeWithArguments` 数组传参，不用字符串拼接。

**同步长任务需可取消可降级。** 成片合成 `FFmpegKit.execute` 在主 isolate 同步执行，无进度无取消无超时，调用方先弹 SnackBar 再 await，`hideCurrentSnackBar` 永不执行导致永久进度条。约定用 `FFmpegSession` + 进度回调 + `cancelExecution` + `Isolate.run`；先 `ffprobe` 探测音轨（缺失则 `anullsrc`），`apad` 必须带 `whole_dur`（默认无限补静音造成成片尾部黑帧）；成功后删除临时文件。

**协议常量需统一枚举。** `agnes_presets.dart` 的 `openai-chat` / `openai-images` / `openai-videos` 与适配器实际分支不一致：LLM 侧 `protocol` 是死字段，用户看到的下拉失去意义；图片 / 视频侧协议字符串不匹配会静默落到默认分支。约定统一枚举 + 适配器显式分支 + 未知协议抛错，不得静默降级。
